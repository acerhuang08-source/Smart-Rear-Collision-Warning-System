# BNO055 軟體裝置層與安全診斷

## 架構與責任

```text
smbus2 SMBus（optional hardware extra）
  → SMBusRegisterIO
  → BNO055Device
  → registers 純轉換函式
  → frozen/slotted measurement models
  → bno055-diagnostic
```

`models.py` 與 `registers.py` 不執行 I/O。`BNO055Device` 只依賴可注入的
register I/O protocol，不建立 SMBus。`smbus.py` 是唯一直接匯入 `smbus2`
的模組，並由 `hardware.py` 在使用者確認硬體後 lazy-load。一般核心匯入
及 `.[dev]` 測試不需要 `smbus2`、`gpiozero` 或 `lgpio`。

BNO055 與 UART adapter、TFMini Plus parser、WarningPolicy、hysteresis、
WarningController 及 LED driver 完全分離。本階段不以姿態、加速度或傾斜
改變警示狀態。

## 裝置生命週期

診斷先驗證 `A0/FB/32/0F` 四個固定 ID，再依序寫入 CONFIGMODE、page 0、
normal power mode、預設 SI／degree units 與 NDOF mode。模式切換使用可注入
的 sleep，遵守 19 ms 與 7 ms 等待時間；測試使用 fake sleep，不會真的等待。
進入 NDOF 後以預設 2 秒 timeout、20 ms interval 有限輪詢 operation mode、
`SYS_STATUS` 與 `SYS_ERR`。唯一成功條件是 mode `0x0c`、status `0x05`、
error `0x00`。未就緒狀態會在 timeout 內繼續等待；非零 error 或 system-error
status 立即失敗；timeout 訊息保存最後一次三個原始值。clock、sleep、timeout
與 interval 都可注入，單元測試不會真實等待。

每筆量測以單次 26-byte block read 讀取 `0x1a–0x33`，再用集中定義的 offset
解析 Euler、quaternion、linear acceleration 與 gravity，使這四組資料來自
同一個連續 block。temperature、calibration、system status 和 system error
仍在之後分別讀取。每筆都要求 mode `0x0c`、status `0x05` 且 error `0x00`；不符合的當筆
不輸出、不計入 valid samples，診斷以非零狀態結束。短讀取、無效 byte、
read/write exception 同樣轉換成清楚的 device error。

`quality.py` 提供集中且完全無 I/O 的 measurement quality assessment。預設
quaternion norm 合理範圍為 `0.5–1.5`，gravity norm 合理範圍為
`5.0–15.0 m/s²`；四個門檻皆可覆寫，且拒絕 bool、string、NaN、infinity、
非正值及 `min >= max`。所有浮點欄位都必須 finite，mode/status/error 仍須為
`0x0c/0x05/0x00`。Euler、linear acceleration 及 calibration 可以全零，因為
靜止、特定方向或尚未校正不代表資料框不完整。

正常完成、Ctrl+C、初始化中途失敗或讀取失敗時都嘗試回到 CONFIGMODE，
再關閉 bus。CONFIGMODE write 與 bus close 會各自嘗試；任一 cleanup 失敗都
使 CLI 回傳非零，且不得輸出 cleanup 成功。

NDOF readiness 後先進入 data-ready polling。預設 timeout 2 秒、interval
20 ms，並同時使用 monotonic deadline 與 `ceil(timeout / interval) + 1`
最大嘗試次數（預設 101），因此 clock 停滯或倒退、sleep no-op 也不會無限
迴圈。狀態正確但 quaternion／gravity 不合理的啟動框只增加
`discarded_startup_samples`，不輸出且不計入有效樣本；第一筆合理資料成為
sample 1，並從此刻開始 sampling duration。正式 sampling 再遇到非有限值、
norm 越界或 fusion state 錯誤時，該筆不計數，增加相應 error counter，立即
非零結束並執行 cleanup。摘要另列第一筆有效資料等待時間與 quality thresholds。
Ctrl+C 摘要標示 interrupted 並回傳 130，零樣本亦回傳非零。

## 實機識別事實與限制

- 模組：GY-BNO055，3.3 V。
- Raspberry Pi 5 I2C bus：1。
- 實際位址：`0x29`。
- CHIP／ACC／MAG／GYR ID：`0xa0 / 0xfb / 0x32 / 0x0f`。
- 20 次唯讀識別全部一致，沒有 I2C error。
- `ST_RESULT=0x0f`。
- 上電時為 CONFIGMODE（`OPR_MODE=0x00`）。
- `SYS_ERR=0x09` 是進入融合模式前的觀察值，不是正常融合結果。

## 安全診斷 CLI

CLI 參數為 `--bus`、`--address`、`--sample-interval`、`--duration`、
`--max-samples`、`--data-ready-timeout` 與 `--confirm-hardware`。bus 預設 1、address 預設 `0x29`，
也接受 `0x28`。至少要提供 duration 或 max-samples，禁止預設無限執行。

未提供確認旗標時，CLI 只列出所選 bus、address、NDOF mode 與預計寫入的
設定暫存器，以 usage code 2 結束。此路徑不載入 `smbus2`、不建立 SMBus、
不讀寫暫存器。本次修正只執行 fake 測試，沒有重新開啟 `/dev/i2c-1`。

## 自動測試

fake bus 測試涵蓋兩個支援位址、四種身分不符、signed little-endian 邊界、
所有比例換算、calibration bit field、26-byte offset、readiness 狀態序列與
timeout、每個 partial-initialization read/write failure、runtime state error、
正常與複合失敗 cleanup、Ctrl+C、零樣本、bounded CLI、多裝置狀態隔離，
以及未確認時零 I/O／零 hardware import。另以隔離注入的假 `smbus2` module
驗證 adapter forwarding、constructor failure、重複 close 與例外傳遞，不會
開啟 `/dev/i2c-1`。

目前完整 suite 為 367 項測試，全部使用 fake bus／clock 或純資料 fixture；
不會開啟 I2C、UART、GPIO 或其他硬體介面。
