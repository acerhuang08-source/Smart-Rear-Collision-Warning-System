# ioRadar701、BNO055、融合與 LED 整合盤點與方案（2026-10-27）

日期／時區：2026-10-27，Asia/Taipei

性質：現地原始碼盤點與建議設計；本輪沒有實作 runtime adapter、開啟裝置、驅動 LED、調整門檻或切換 service。

## 建議結論

建議保留現有 ioRadar701 單獨 `offline|live` 與舊 TFMini LIVE 完全可用，另建一個
**單程序、單 UART owner 的 ioRadar701＋BNO055 整合入口**。新入口先以 shadow
模式完成 target 選擇、host-monotonic 因果配對、距離趨勢、BNO055 自身動作證據、
分類與「候選 LED 決策」的顯示／記錄；在下列待決策事項確認且硬體測試另經授權後，
才由同一資料流啟用 GPIO 輸出。

核心原則：只把完整、未過期且被明確選中的 target 之 `hypot(X,Y)` 當作距離序列；
X、Y 與 Vx 仍個別保存，**Vx 不送入既有 closing-rate、TTC 或速度估計**。target
切換或失效時先清除該 target 的距離趨勢與分類狀態，絕不把不同 ID／不同物體的距離
直接相減，也不把零目標或缺資料補成 0 m、0 m/s、正常分類或綠燈。

## 現地資料流

```text
/dev/ttyAMA0 (唯一 owner，230400/8N1)
  -> IoRadar701StreamParser.feed(bytes)
  -> RadarStateTracker.observe(frame, host_monotonic)
  -> 完整／零目標／未完整／過期／錯誤 RadarSnapshot
  -> RadarTargetSelector（新；保留、選擇、切換理由）
  -> SelectedRadarRange(hypot(X,Y), target_id, cycle completion receipt time)
                                      \
/dev/i2c-1 -> BNO055Device -> quality -> latest causal motion matcher
                                      /
  -> RadarRelativeMotionAdapter（新；重用 trend / own-motion / classifier）
  -> RelativeMotionAssessment + 距離 WarningPolicy 候選
  -> 整合 availability/decision（新；仍保留原始理由）
  -> 固定中文面板／plain + capture/fusion/decision logs
  -> ThreeColorLedDriver（只有明確啟用 GPIO 的後續階段）
```

這是 host-monotonic 軟體關聯，不是雷達與 BNO055 的硬體同步，也不代表已量得感測器
內部時間或端到端延遲。

## 多目標選擇與狀態重置

新增 I/O-free `RadarTargetSelector`，輸入只能是當輪 `RadarSnapshot` 與 cycle completion
host-monotonic timestamp，輸出包含 `selected_target | None`、`target_id`、
`distance_m`、`selection_reason`、`continuity_key` 與 availability。規則固定如下：

1. 只有 `state=live`、`cycle_complete=true` 的當輪 target 可入選；零目標、未收齊、
   bytes/status/target stale、serial error 全部輸出不同 availability，不產生虛構距離。
2. target 的 X、Y、`hypot(X,Y)`、Vx、energy 全部保存；排序與距離趨勢只使用
   `hypot(X,Y)`。Vx 只顯示／記錄，不參與 closing rate、TTC 或 warning。
3. 必須先確認雷達相對車體的座標與有效偵測區，才能用可設定的 rear-corridor 篩選。
   corridor 邊界是待決參數，本文件不填入假門檻。
4. 已選 target ID 仍存在且符合 eligibility 時優先保持；ID 只作短期連續性提示，
   不是永久身分。
5. 新候選必須比現 target 近至少 `switch_margin_m` 並持續
   `switch_confirmation_seconds` 才切換；兩個參數必須由 replay／場景驗證後批准，本輪
   不給數值。沒有 current target 時，依「符合 corridor 後最小 hypot」決定候選，
   並保存所有候選與拒絕理由，不能只取 decoded 第一筆。
6. target 消失、N=0、未完整、stale/error 或確認切換時，先發出 discontinuity；
   清除 distance trend 與 classifier 的 candidate/baseline，再接受新 target。BNO
   own-motion window可在仍健康時保留；BNO 自身 gap/invalid 則依原元件重置。

如此可以避免 ID 0→1 的兩個距離被當成同一物體的速度。也不會把 T4 的 N=0
自動解釋成「本人離開」。

## 融合、警示與失效映射

建議用一個新的 `IntegratedRadarAvailability` 保留至少：`LIVE_SELECTED`、
`NO_TARGETS`、`INCOMPLETE_CYCLE`、`RADAR_STALE`、`RADAR_ERROR`、`BNO_NOT_READY`、
`SYNC_UNMATCHED`、`FUSION_WARMUP`。它和既有四值 `WarningState` 分層，避免 UI／log
失去原因。

在不改現行門檻的前提下，唯一建議路徑是：

- `LIVE_SELECTED`：selected `hypot` 轉為等值 centimetres，送既有
  `WarningPolicy.classify_distance_cm` 和 stabilizer，產生原距離警示候選；同一 range
  序列另送 radar fusion adapter 與 BNO055 產生 relative assessment。
- `NO_TARGETS`：不產生距離／融合樣本，重置 target-bound history。內部狀態保持
  `NO_TARGETS`，不得顯示 SAFE 或綠燈。
- 未完整、stale、radar error、BNO 不 ready、sync unmatched 或 fusion warmup：保留
  具體 availability/reason，不餵 0 值；按現行 missing/invalid fail-safe 候選為
  `SENSOR_FAULT`，不能沿用先前 LED 狀態。
- shadow 階段同時記錄 distance candidate、relative assessment、availability 與
  「若啟用 LED 的候選」，但不建立 GPIO output。
- GPIO 啟用前必須批准一張 final decision table，尤其是 `NO_TARGETS` 最終要投影成
  紅+黃 fault、全熄或新增燈號。本輪不把它靜默定為任何實體輸出。relative class
  如何升降 DANGER/WARNING 也尚無現行 policy，因此同樣不得私自接燈。

這保留原距離門檻、hysteresis、baseline、persistence 與 fail-safe；也明確承認目前
不存在已驗證的「relative classification → WarningState」產品規則。實際啟燈以前，
shadow replay 是必要的安全門檻，不是另一條架構。

## 手動啟動、停止與記錄設計

未來入口須維持以下生命週期；本文件刻意不提供尚不存在的 live 命令：

1. 顯示 UART=ttyAMA0/230400/8N1、I²C bus/address、shadow/GPIO 模式、風險與輸出目錄。
2. `--confirm-hardware` 且互動 Enter 以前：不 import hardware backend、不建 capture、
   不開 UART/I²C/GPIO。
3. Enter 後先用現有只讀 preflight 檢查 ttyAMA0 與 I²C owner；busy 就退出，不 kill、
   不操作 `tfmini.service`。UART open 必須 exclusive/TIOCEXCL，整個程序只有一個 reader。
4. 建立新 capture 目錄，開 raw／decoded／events／fusion／decision files；初始化 BNO055
   NDOF 並通過 quality readiness，再開始輸出完整 radar cycles。GPIO 階段未批准時不
   import gpiozero。
5. panel 與 plain 都顯示目前所有 targets、selected ID／理由、cycle/freshness、BNO
   quality/calibration、sync age/status、trend、classification ready/candidate/reason、
   distance warning candidate 與 LED enabled/disabled。stale 時清除數值欄或明示舊值，
   不冒充即時。
6. Ctrl+C、signal、UART/I²C/storage/output error 都進同一 finally：若 GPIO 已啟用，
   先 `all_off` 並 close；再 close radar serial；BNO055 回 CONFIG mode 並 close bus；
   每一 cleanup 都繼續嘗試並彙總錯誤；最後 flush/close capture、寫 summary/metadata、
   還原 terminal。
7. `raw.bin` 仍是原始 UART bytes；decoded/cycle/selection/fusion/decision 各自帶 host
   monotonic 及 wall start metadata。記錄 target switch/reset、no-target、stale、sync
   與 LED candidate/actual，不只記最終顏色。

## 必要的硬體無關測試

- parser regression：現有真實封包、任意 chunk、T4 offset-0 `0xff`、checksum recovery，
  且 standalone offline 結果不變。
- completed-cycle emission：N=0、N>0 收齊、下一 status 前未收齊、重複／額外／孤立、
  stale/error、每輪只 emit 一次。
- selector：不能取第一筆；hold current、候選距離排序、corridor reject、switch margin／
  confirmation、ID 消失、N=0、stale、不完整；每種結果有 deterministic reason。
- discontinuity：切 target、no-target、stale/error 後 distance trend／classifier reset，
  確認跨 target 不會產生 closing rate；健康 BNO window是否保留符合設計。
- causal sync：non-future、age=0.2 邊界、future/stale/no/invalid、同一 motion 被多個
  radar cycles 配對但只向 OwnMotionEstimator 提交一次。
- units/semantics：只用 `hypot(X,Y)` range；Vx 無法流入 trend/TTC；metre/cm 轉換與
  舊 TFMini 結果完全等價。
- fusion regression：既有 baseline、warmup、persistence、大 gap、不健康 sync 與
  constant-velocity 不可觀察限制不變。
- warning/decision：N=0、不完整、stale/error、BNO not-ready、fusion warmup 不會變成
  SAFE/green或沿用舊狀態；approved final table 的每格都有測試。
- fake lifecycle：Enter 前零 I/O、busy 拒絕、唯一 UART owner、部分初始化、正常／
  Ctrl+C／signals／read/write/close error、全部 cleanup 嘗試、GPIO all-off、capture
  received=persisted 與可重啟。
- 六組 2026-10-27 raw replay golden：計數與週期不變，輸出 selection/fusion shadow
  trace 可重現；不得把 T3/T4 的座標自行標成操作員動作。
- 原 `rear-warning-live`、`ioradar701 offline|live` targeted regression，確保兩個舊入口
  未被新 generic boundary 破壞。只有跨模組變更通過後才擴大 full suite。

## 回退方式

- 新入口、新 selector、radar adapter 與 decision layer 全部是加法；預設不取代
  `python -m rear_warning.cli.ioradar701 offline|live` 或 `rear-warning-live`。
- 不改 systemd unit、開機設定、UART alias、baud、接線或校正檔。停止新程序並確認
  ttyAMA0 已關閉，即可回用 standalone ioRadar 或由操作員恢復既有 TFMini 工作流。
- shadow 是預設；GPIO 必須另有明確啟用條件。發現 selection／fusion 問題時關閉新
  入口即可，不需回寫 capture 或改 parser。
- capture schema 使用新 version／新增檔案，不覆寫原五檔與六輪證據；rollback 不需
  資料轉換。

## 真正影響下一步的待決策／未知

1. ioRadar X/Y 軸相對車體與後方的實際方向、有效 rear corridor，以及 Vx 的物理
   符號／定義未驗證；目前只可安全使用幾何距離作 shadow trend。
2. `switch_margin_m`、`switch_confirmation_seconds`、acquire confirmation 與 corridor
   參數尚無實測依據，不能私設。
3. target ID 是否及多久可作短期連續性提示沒有原廠／場景證據；必須容許隨時換 ID。
4. `NO_TARGETS` 的實體 LED 投影，以及 relative classification 如何影響距離警示，
   需要產品／安全決策。未決前不得啟用 LED。
5. 實際三色燈型、BCM 17/27/22 接線、active-high 與共同端未由本輪硬體確認；現地
   程式預設不等於已裝配證據。
6. BNO055 在車體上的 axis map、安裝姿態、要載入的 calibration profile 與可接受的
   calibration 最低值尚未確認。OwnMotionEstimator 也不能觀察所有等速直線自身運動。
7. ioRadar 距離精度、道路環境、warning thresholds 對新雷達是否合適、端到端時間與
   長期可靠性都未驗收；保留舊數值不代表已證明適用。

這些缺口阻擋的是「啟用融合驅動實體 LED」，不阻擋先完成 selector、replay、shadow
資料流及硬體無關測試。
