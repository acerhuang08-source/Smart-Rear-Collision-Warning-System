# TFMini Plus＋BNO055 同步資料採集層

## 定位與邊界

本層執行 Time Association（時間關聯），不是數學上的 Sensor Fusion。TFMini
Plus 約 100 Hz、BNO055 初始設定約 10 Hz，兩者沒有共同硬體 trigger，也不會
在完全相同的瞬間更新。本層只保存共同 monotonic 時間基準、執行 causal
matching、判斷 motion freshness、統計品質並選擇性輸出 CSV。

本階段沒有實作 closing speed、TTC、距離濾波、碰撞演算法、WarningPolicy 或
LED state，也沒有把 BNO055 資料接入現有警示鏈。

## 分層架構

```text
TFMiniPlusSerialDevice ─→ TimedDistanceMeasurement ─┐
                                                   ├→ SensorSynchronizer
BNO055Device ──────────→ TimedMotionMeasurement ───┘
                                                           ↓
                                              SynchronizedSensorSample
                                                           ↓
                                         diagnostic output / optional CSV
```

- `models.py`：frozen/slotted timed 與 synchronized models，只做 intrinsic
  validation，不執行 I/O。
- `synchronizer.py`：每個 instance 保存自己的最新 motion sample，執行無 I/O
  causal matching。
- `coordinator.py`：注入兩個 device、共同 monotonic clock、sleep 及 sink，以
  單執行緒 deadline scheduler 採集。
- `csv_sink.py`：只在使用者明確指定時 exclusive-create CSV，序列化 matched
  與 unmatched records。
- `sensor-sync-diagnostic`：confirmation gate、硬體生命週期、統計、錯誤與
  cleanup orchestration。

## 資料模型與驗證

`TimedDistanceMeasurement` 與 `TimedMotionMeasurement` 保存原始 measurement 及
canonical monotonic timestamp；其明確語意是 coordinator 在完整成功 read 後，
以共同注入 clock 取得的主機讀取完成時間。既有
`BNO055Measurement.monotonic_timestamp` 則由 BNO055 device 在 measurement block
read 前取得，保留原本語意但不參與 matching 或 CSV timestamp。兩者不得描述成
同一 capture time。`SynchronizedSensorSample` 保存距離、可選 motion、
兩個 timestamp、可選 age 與 `SensorSyncStatus`：

- `MATCHED`
- `NO_MOTION_SAMPLE`
- `STALE_MOTION_SAMPLE`
- `FUTURE_MOTION_SAMPLE`
- `INVALID_DISTANCE_SAMPLE`
- `INVALID_MOTION_SAMPLE`

Timestamp 必須是 finite、非負 number，拒絕 bool、string、NaN、infinity 與
負值。`MATCHED` 必須有 motion measurement、motion timestamp、非負 age，且
age 必須等於 distance timestamp 減 motion timestamp。Unmatched status 的 age
必須是 `None`，不得偽造同步品質。

## Causal latest-sample matching

每筆 distance 只可使用 capture time 不晚於 distance 的最新 BNO055 sample：

```text
motion_age = distance_timestamp - motion_timestamp
```

- age `0`：matched。
- age 等於 maximum：matched。
- age 大於 maximum：stale，不計入 matched／age statistics。
- motion timestamp 晚於 distance：future，不得當作成功匹配。
- 尚無 motion：no motion。
- 通過品質驗證的新 motion 取代舊 motion；invalid update 會拋出例外且不覆蓋
  仍有效的 latest motion。Coordinator 對此 fail-fast，不會沿用舊資料繼續採集。
- 同一 motion 可合法配對多筆高頻 distance。

Maximum-age邊界只容忍IEEE-754表示誤差，現行公式與production一致：

```text
age_tolerance_seconds =
max(1e-12, 4 × ulp(maximum_age_seconds))
```

`ulp`是該maximum-age浮點數附近兩個相鄰可表示值的間距。這不是額外允許的
資料延遲，也不使用可能隨大型monotonic timestamp放寬的relative tolerance。
Future判斷在容差比較前執行，因此未來sample不會被容差放行；CSV仍保存實際
計算的age，不會為了通過邊界而改寫timestamp或age。

預設 `bno055_interval_seconds=0.1`、`maximum_bno055_age_seconds=0.2`。兩者只是
可覆寫初始值，不是道路實測後的最終參數。

## 單執行緒 scheduler

Coordinator 先以同時受 monotonic deadline 與最大嘗試次數限制的 data-ready
階段取得第一筆品質有效 BNO055 measurement。之後以 monotonic phase deadline
約每 0.1 秒讀取一次 BNO055，再繼續 TFMini UART read。下一 deadline 由前一
deadline 推進，不使用 `sleep(interval)` 當作排程基準，因此不累積讀取時間
造成的漂移；若落後多個 period，也只讀一次並以算術跳至下一個未來 deadline。

正式 sampling duration 在 data-ready 完成後才開始，且正值 duration 至少嘗試
一次 UART read。所有 canonical timestamps 來自同一個注入 clock，wall clock
不參與 matching。每次 UART read 回傳後才取得 distance timestamp；下一次
blocking UART read 前會重新檢查 BNO deadline。落後時只讀一次 BNO，deadline
以算術跳期，不執行 catch-up burst。

同步 CLI 的 `--uart-timeout` 預設為 0.02 秒，必須是 finite 正數且不得大於
`--bno055-interval`。既有 TFMini device 每次 `read_measurements()` 執行一次底層
serial read；timeout 限制該 blocking read，但作業系統排程與驅動仍可能造成額外
延遲。因此本層統計 BNO deadline lateness maximum／average 與 missed periods，
不宣稱單執行緒 scheduler 具有硬即時保證。

Scheduler 另有 finite iteration cap，所以 constant／backward clock 加 no-op
sleep 也不會形成無限迴圈。整體必須提供 duration 或 max samples。

## CLI 與 import safety

`sensor-sync-diagnostic` 支援：

- TFMini：`--port`、`--baudrate`、`--uart-timeout`。
- BNO055：`--i2c-bus`、`--bno055-address`、`--bno055-interval`、
  `--maximum-bno055-age`、`--data-ready-timeout`。
- Bounds／output：`--duration`、`--max-samples`、`--csv-output`、
  `--confirm-hardware`。

`--max-samples` 限制成功提交的同步 records 總數，包含 MATCHED 與 unmatched；
不是要求取得指定數目的 MATCHED。Duration 與 max-samples 同時存在時任一先到
即停止，zero MATCHED 仍回傳失敗。

未確認路徑只顯示 UART、I2C、time-association、CSV 與預計硬體動作，回傳 2。
它不載入 `serial`、`smbus2`、`gpiozero`、`lgpio`，不建立 UART／SMBus／CSV，
也不寫 BNO055 registers。Hardware factories 只在 confirmation gate 之後
lazy-load。2026-08-30 已執行一次另行授權的 stationary bounded confirmed
capture；結果與限制記錄於下方及獨立實測報告。

## CSV schema 與安全性

CSV 欄位依序包含 sequence、distance/BNO055 timestamps、motion age、sync
status、distance、signal strength、TFMini temperature、Euler、quaternion、
linear acceleration、gravity、BNO055 temperature、四項 calibration、operation
mode、system status、system error。

只有明確提供 `--csv-output` 才建立檔案，使用 exclusive-create mode；目標已
存在即失敗且不啟動硬體，不提供 overwrite。每次 row write 後 flush；write 與
flush 都成功後才提交 sequence、record、matched 與 age 統計。失敗 row 不計入
committed records。底層 stream 可能在 flush error 前已寫入部分 bytes，因此檔案
不是原子交易且不會自動刪除，以保留診斷證據。正常、
error、Ctrl+C 都再次嘗試 flush／close。Unmatched 缺少的 motion 欄位留白；
非有限值不寫入數值欄。CSV 不包含 closing speed、TTC、warning 或 LED 欄位。

## 錯誤、cleanup 與統計

BNO055 readiness／I2C／quality error、serial/parser exception、CSV error 會立即
終止。UART empty read 只增加 counter，不產生 record。Stale／no-motion record
可輸出但不算 matched。成功至少需要一筆 matched sample；Ctrl+C 回傳 130，
任何 cleanup failure 都不得回傳成功。

Cleanup 依序嘗試 UART close、BNO055 CONFIGMODE／SMBus close、CSV flush／close，
不因前一項失敗跳過後續資源。主要錯誤與多個 cleanup errors 都會輸出。

Startup BNO reads 與正式 sampling BNO reads 分開計數；rates 只使用 data-ready
完成後至 sampling 結束前的 sampling elapsed。Total elapsed 另含初始化、
data-ready 與 cleanup，慢 cleanup 不會降低 sampling rate。

摘要包含 committed records、valid distances、startup/runtime BNO measurements、matched/no-motion/stale/future、
UART empty reads、serial/parser、BNO055、CSV errors、matched-only motion age
minimum/maximum/average、deadline lateness、missed periods、三種 rate、sampling／
total elapsed、interrupted 與 cleanup status。

## 2026-08-30 首次實體同步採集

首次 10 秒 stationary capture 使用 `/dev/ttyAMA0`、115200 baud、UART timeout
0.02 秒、I2C bus 1、BNO055 address `0x29`、BNO interval 0.1 秒、maximum age
0.2 秒及 data-ready timeout 2.0 秒。CLI 與 log pipeline exit code 均為 0；摘要
記錄 994 筆 valid distance／total／matched records、99 筆正式 BNO reads、startup
reads/discards 4/3，且 no-motion、stale、future、invalid、UART empty、missed
periods、parser/serial、BNO055 與 CSV errors 均為 0。Sampling/total elapsed 分別
為 10.009/10.190 秒，distance/matched rate 為 99.310 Hz，BNO rate 為 9.891 Hz。

離線完整解析 CSV 後，994 筆 sequence 為 1–994 且無缺號、重複、截斷或不完整
欄位；全部 timestamp finite 且單調，motion 不晚於 distance。每筆 age 都精確
等於兩個 CSV timestamp 的差，範圍 `0.020086062999325804`–
`0.10520604599878425` 秒，平均 `0.054566798368252796` 秒，均符合 0.2 秒及既有
浮點容差。全部正式資料通過 finite、quaternion norm 0.5–1.5、gravity norm
5–15 m/s² 與 `0x0c/0x05/0x00` 條件。CSV 有 100 個不同 canonical motion
timestamps，說明一筆低頻 motion 合法配對多筆 distance；994 matched records
不等於 994 次 BNO read。完整距離範圍為 73–73 cm；calibration 出現
`(0,0,0,0)` 與 `(0,3,0,0)`，最後為 `(0,3,0,0)`，不宣稱完整校正。

三筆 startup discard 由 CLI 摘要證明，且 CSV 中沒有不合格正式資料；但被
discard 的原始 measurement 本來就不寫入 CSV/log sample row，因此無法由兩個
原始檔逐筆重建。CSV 的 `bno055_timestamp` 依 schema 與實作契約是 wrapper
read-completed timestamp，age 的數值也與該欄一致；原始 block-read timestamp
未被保存，故僅靠 CSV 無法做兩種 timestamp 的直接數值對照。

包裝腳本原始 exit code 為 1：診斷後 UART 已釋放、服務恢復命令完成且顯示
active/running，但當時的恢復後 UART holder 確認未通過。原因尚未查明，不將它
寫成已證實的啟動時序問題。使用者後續提供的唯讀查驗顯示服務 MainPID 10502、
active/running、`/dev/ttyAMA0` holder 為 `topics` PID 10502 `python3`，並確認
BNO055 `OPR_MODE=0x00`；這些是補充證據，不是原始腳本成功證據，也未補寫原始
log。

本次驗證的是共同主機 monotonic clock 上的因果配對，不是硬體同時採樣；100%
matched 也不表示真實量測瞬間完全同步。完整 calibration、道路動態、長時間
可靠性、sensor fusion、closing speed、TTC 與警示決策仍未完成。
