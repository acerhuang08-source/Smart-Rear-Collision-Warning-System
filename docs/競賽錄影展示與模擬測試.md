# 競賽錄影展示與模擬測試

## 交付範圍與狀態

本工具以決定性的合成資料展示既有融合演算法，不讀取 UART、I²C 或 GPIO，
不控制 LED，也不連線外部服務。Python 端的實際資料流為：

```text
合成 TFMini Plus／BNO055 measurement
  → SensorSynchronizer
  → RelativeMotionFusionAdapter
  → DistanceTrend／OwnMotionEvidence／RelativeMotionAssessment
  → WarningPolicy／WarningStateStabilizer（獨立的距離警示模擬）
  → JSON trace 與單檔離線 HTML
```

HTML 只播放 Python 預先算好的公開輸出，不在 JavaScript 重新實作分類規則。
播放倍速只改變畫面更新間隔；樣本 timestamp、門檻與推理結果不變。每個情境
各自建立新的 synchronizer、adapter、policy 與 stabilizer，不共用 baseline。

目前狀態：純軟體展示已完成；實體硬體本輪未操作；影片尚未拍攝；融合分類
仍未接入正式 LED 控制。

## 產生與開啟

在 repository 根目錄執行：

```bash
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src .venv/bin/python \
  -m rear_warning.demo.cli \
  --output demo/rear-warning-demo.html \
  --trace-output demo/rear-warning-demo-data.json \
  --force
```

成功時會列出兩個輸出路徑、Git HEAD、dirty 狀態及 `hardware_io=false`。
`--force` 只覆寫命令列明確指定的兩個檔案；不提供時，如任一檔案已存在，
程式會拒絕覆寫。可將臨時輸出放在 `demo/output/`，該目錄已被 Git 忽略。

離線開啟 `demo/rear-warning-demo.html`，不需要 HTTP server 或網路：

```bash
xdg-open demo/rear-warning-demo.html
```

也可以從檔案管理員雙擊。錄影前使用瀏覽器全螢幕，確認右上角持續顯示
「合成資料模擬」。操作列提供播放／暫停、重播、進度拖曳、情境切換及
0.5×／1×／2×／4×。若要剪掉暖機等待，可用 2× 或 4× 並讓倍率控制保持入鏡；
不得修改 JSON timestamp 或 production 門檻。

JSON trace 保存：scenario ID、資料來源、每筆輸入與同步狀態、sample timestamp、
公開演算法輸出、各情境摘要、實際預設參數、產生時 Git HEAD 與 dirty 狀態。
`distance_cm: null` 表示該筆是無效距離，不能解讀成 0 公尺的有效量測。

## 四個情境

產生器使用 20 Hz distance 與 10 Hz motion。這是為了讓離線檔案精簡；仍符合
現行距離趨勢與 motion window 的時間條件，且一筆 motion 會被多筆 distance
重用，adapter 只把每個唯一 motion timestamp 計入一次。

### A：先穩定，再持續接近

- 0–1.50 秒：3.60 m 穩定距離及無明顯自身動作，累積 trend、motion window
  與 0.8 秒 stationary baseline。
- 1.55–3.50 秒：以 0.60 m/s 合成斜率縮短距離。
- 畫面先顯示暖機與候選持續；在 baseline 與 0.4 秒 target persistence 均成立後
  才能提交 `TARGET_APPROACH`。
- baseline 超過現行 1.0 秒有效期後，分類忠實回到 `UNCERTAIN`。

### B：自身移動造成距離縮短

- 距離以 0.50 m/s 合成斜率縮短。
- 每個新 motion sample 提供 0.8 m/s² X 軸線性加速度，並累積 3° 旋轉。
- 畫面顯示平移／旋轉是否達判定條件，並在 persistence 成立後提交
  `STATIC_OR_SELF_APPROACH`。
- 這只表示接近可由觀察到的自身動作解釋，不證明目標一定是牆或靜止物體；
  也不是實體平台驗證。

### C：接近途中才啟動

- 從第一筆起即以 0.50 m/s 合成斜率縮短距離。
- motion 沒有明顯平移或旋轉證據，但啟動前沒有 stationary baseline。
- 即使 distance trend 與 own-motion window 已 ready，仍全程為 `UNCERTAIN`，
  不會把「沒有加速度」誤當成已證明靜止。

### D：資料失效與恢復

- 先以有效穩定資料建立 baseline。
- 暫停更新 motion，讓既有資料先超過 classifier freshness，再由 synchronizer
  產生 `STALE_MOTION_SAMPLE`。這是軟體時間序列，不代表實際拔線。
- 恢復有效 motion 後重新累積 baseline。
- baseline 再次 ready 後開始持續縮短距離，確認畫面出現 target candidate；接著
  注入 `distance_cm=0`，由既有同步 validity predicate 產生
  `INVALID_DISTANCE_SAMPLE`。無效距離不進入 distance trend，pending candidate
  也必須被清除。
- stale 與 invalid distance 都立即退回 `UNCERTAIN` 並清除 baseline；後續有效
  資料必須重新累積，不沿用最後一筆正常分類。

## 分類用語界線

| Enum | 畫面用語 | 不可延伸宣稱 |
| --- | --- | --- |
| `STABLE_OR_RECEDING` | 距離穩定或遠離 | 不等於道路環境安全 |
| `STATIC_OR_SELF_APPROACH` | 接近可能由自身動作造成 | 不證明目標一定靜止 |
| `TARGET_APPROACH` | 符合目標接近判定條件 | 不代表辨識車種或絕對車速 |
| `UNCERTAIN` | 資料不足或情況不確定 | 不得為畫面效果隱藏 |

「沿感測方向的接近速率」是 range slope 的衍生量，不是目標車速。
「平移／旋轉達判定條件」是短時間 IMU evidence，不是精準車速，也不代表
已確定靜止。「距離警示模擬」只使用既有 WarningPolicy／stabilizer，和融合
分類並列，不建立融合到 LED 的新映射。

## 實體距離與 LED 拍攝指南（待操作員執行）

以下步驟會開啟真實 UART 並切換 GPIO。**本輪未執行。**只有在操作員確認
接線、供電、場地及服務影響，並針對該次測試明確同意後才能執行；不得把本節
當成永久硬體授權。

### 1. 拍攝前確認

1. 固定 Raspberry Pi、TFMini Plus 與 LED 板，避免移動時拉扯導線。
2. 確認 TFMini 感測方向與紙板／模型車表面近似垂直；地面以捲尺標示距離。
3. 確認穩定供電。紅／黃／綠 LED 應分別接 BCM GPIO17／27／22，且各有獨立
   限流電阻；實體 pin 為 11／13／15。
4. 確認沒有人或程序正在使用 GPIO17、27、22。確認 `/dev/ttyAMA0` 是否由
   `tfmini.service` 占用；同一 UART 不可同時由兩個程序開啟。
5. 在場記錄拍攝日期、Git HEAD、`git status --short`、使用參數、資料來源與
   實際觀察。尚未執行者填「待拍攝／待驗證」，不可預填通過。

### 2. 啟動與停止

由操作員確認後，先安全停止既有 UART owner，再執行有時間上限的完整警示鏈：

```bash
sudo systemctl stop tfmini.service
```

```bash
GPIOZERO_PIN_FACTORY=lgpio rear-warning-diagnostic \
  --port /dev/ttyAMA0 \
  --baudrate 115200 \
  --timeout 0.1 \
  --duration 60 \
  --confirm-hardware
```

正常完成或需要提早停止時按 `Ctrl+C`；程式應關閉 UART、熄滅 LED 並釋放
GPIO。摘要只有 `cleanup_completed=true` 且 exit code 0 才算完整成功。完成後由
操作員恢復原服務並確認狀態：

```bash
sudo systemctl start tfmini.service
```

```bash
systemctl is-active tfmini.service
```

若啟動、量測或 cleanup 失敗，停止拍攝並記錄完整輸出；不要讓第二個程式搶開
UART，也不要在通電時拔除 UART、GPIO、I²C 或電源線。

### 3. 距離與遲滯拍攝順序

用紙板或模型車沿感測軸緩慢移動。候選位置不是精密校正保證；場地與捲尺若無法
可靠命中 1 cm，應拍攝量測畫面與移動方向，不宣稱單次擺位就是門檻驗證。

| 順序 | 移動方向／候選距離 | 依現行規則預期 | 要觀察的差異 |
| --- | --- | --- | --- |
| 1 | 由遠處到 3.21 m | 綠燈 `SAFE` | 建立由遠處開始的狀態 |
| 2 | 繼續靠近到 3.20 m | 仍可能維持綠燈 | 3.20/3.21 是解除邊界，不是進入警戒邊界 |
| 3 | 靠近到 3.00 m | 黃燈 `WARNING` | 進入警戒 |
| 4 | 靠近到 1.50 m | 黃燈 `WARNING` | 正好 1.50 m 不進入危險 |
| 5 | 靠近到 1.49 m | 紅燈 `DANGER` | 進入危險 |
| 6 | 退遠到 1.69 m | 維持紅燈 | danger 遲滯保持 |
| 7 | 退遠到 1.70 m | 黃燈 `WARNING` | danger 解除 |
| 8 | 退遠到 3.20 m | 維持黃燈 | safe 解除門檻正好 3.20 m 仍警戒 |
| 9 | 退遠到 3.21 m | 綠燈 `SAFE` | warning 解除 |

### 4. 模擬畫面與實體畫面的誠實標示

- 只有接到實際量測資料的畫面才可標「即時」。本離線 HTML 永遠標「合成資料模擬」。
- 本 HTML 不控制 LED。不可用剪接暗示畫面上的融合分類正在驅動實體燈號。
- B 情境若要另拍實體平台動作，必須先確認 BNO055 採集入口、校正設定與場地，
  並另行取得硬體操作同意。目前沒有 production 融合到 LED 的實體展示入口；
  可拍平台動作，再接一段清楚標示的合成模擬。
- 斷線／invalid 優先用 D 情境的軟體注入畫面，不要求通電中拔線。

| 75–95 秒 | 合成模擬 B | 「同樣是距離縮短，但平移與旋轉證據成立，因此分類保留自身動作的解釋。」 |
